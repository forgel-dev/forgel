## Overview

Раздел установки в README клиента Forgel Code опирается на pipx, которого нет в обычной поставке Python, поэтому «одна команда» на деле требует сначала поставить pipx и тянет зависимости. Задача — переписать раздел установки и обновления так, чтобы основной и единственный обязательный путь был обычным pip, доступным сразу после установки Python, добавить подсказки про расположение исполняемого файла, PATH и запасной запуск через `python3 -m forgel_code`, оставить pipx одной необязательной строкой для изоляции и закрыть это двумя проверками: за порядком команд в README и реальной установкой через pip без сети. Код клиента и его контракт с движком не меняются.

## Goals

- В README репозитория `code` основной путь установки — обычный pip, который ставится вместе с Python: первая команда установки должна быть вида `python3 -m pip install` с закреплённой ревизией (тег, коммит или точная версия), не с плавающей веткой по умолчанию.
- Показать вариант установки в виртуальное окружение и вариант с `--user` для системного Python, когда окружение не создаётся.
- Объяснить, куда pip кладёт исполняемый файл `forgel-code` (каталог bin виртуального окружения или пользовательский каталог скриптов pip) и как поправить PATH, если команда не находится.
- Дать запасной запуск без зависимости от PATH: `python3 -m forgel_code` (модуль запуска уже есть в пакете), с примером проверки версии.
- Переписать раздел обновления: обновление — установка более новой закреплённой ревизии через `python3 -m pip install --upgrade`/`--force-reinstall`, включая случай, когда номер версии не изменился, а коммит другой.
- pipx остаётся не более чем одной строкой, явно помеченной как необязательный вариант для изоляции, и размещается после инструкций для pip.
- Сохранить существующие ограничения, о которых README уже говорит: сборка без зависимостей и без сети, editable-установка не поддерживается, движок `forgel` должен быть доступен через PATH или `--engine`/`$FORGEL_ENGINE`.
- Добавить проверку документации: первая команда установки использует обычный pip, а pipx встречается только позже и с пометкой о необязательности.
- Добавить проверку установки: клиент ставится обычным pip во временный каталог без обращения к сети из локального исходного дерева и после этого команда `forgel-code` и запуск через модуль работают и печатают версию.
- Не менять файлы пакета `forgel_code/` и вызовы движка; поведение клиента остаётся прежним.

## Acceptance Criteria

- **AC-1**: Первый блок команд в разделе установки README содержит `python3 -m pip install` с закреплённой ревизией и не требует pipx.
- **AC-2**: README показывает установку в виртуальное окружение и с `--user`.
- **AC-3**: README объясняет, где искать исполняемый файл, как поправить PATH и как запустить клиент через `python3 -m forgel_code`.
- **AC-4**: pipx упоминается не более одного раза, помечен как необязательный и стоит после инструкций для pip.
- **AC-5**: Раздел обновления описывает переход на более новую закреплённую ревизию через pip, в том числе при неизменившемся номере версии.
- **AC-6**: Тест документации проходит: он падает, если первая команда установки перестала быть обычным pip или если pipx оказался раньше и без пометки о необязательности.
- **AC-7**: Тест установки проходит: во временном каталоге без сети клиент ставится обычным pip, `forgel-code --version` и `python3 -m forgel_code --version` печатают установленную версию, код возврата 0.
- **AC-8**: Существующий набор тестов клиента проходит без изменений в поведении.
- **AC-9**: В диффе нет изменений файлов пакета `forgel_code/`.

## Assumptions

- Задача относится к репозиторию `code`: его README.md описывает установку Forgel Code (`pipx install "git+https://github.com/forgel-dev/code@v0.1.0"`, исполняемый файл `forgel-code`), а pyproject.toml объявляет `name = "forgel-code"` и точку входа `forgel_code.cli:main`; обсуждаемый раздел установки находится именно там. Репозиторий `main` — движок (src/forgel, registry, jurisdiction) и остаётся нетронутым.
- Запасной запуск через `python3 -m forgel_code` возможен: в пакете есть `forgel_code/__main__.py`.
- Проверка установки выполняется из локального исходного дерева с отключённым индексом пакетов и без изоляции сборки, чтобы не ходить в сеть.
- Пометка о необязательности pipx формулируется по-английски вместе с остальным README.
