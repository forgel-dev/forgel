## Overview

Документация по установке ведёт с pipx, которого нет в обычной поставке Python, а его установка тянет цепочку зависимостей, поэтому обещанная одна команда оказывается несколькими и процесс зависает. Раздел установки переписывается так, чтобы основной и достаточный путь был обычным pip: закреплённая версия, установка в виртуальное окружение и с --user, подсказка про PATH и запасной запуск через модуль. pipx остаётся только необязательной альтернативой и никогда не идёт первой. Путь обновления даётся тоже через pip. Добавляются проверки, удерживающие этот порядок, и проверка реальной установки через pip во временный каталог без сети.

## Goals

- Раздел установки начинается с обычного pip, доступного вместе с Python (`python3 -m pip`); никакой предварительной установки другого инструмента не требуется.
- Основная команда ставит закреплённую версию — тег, коммит или точный номер — и показана для двух обычных случаев: в виртуальное окружение и с `--user` для системного Python.
- Заголовки читаются как выбор одного из двух равноценных вариантов установки через pip, а не как последовательность обязательных шагов.
- Описана особенность PATH при установке для пользователя: где pip кладёт исполняемый файл (`~/.local/bin` в Linux, `~/Library/Python/<версия>/bin` в macOS), как добавить это в PATH и как запускать через `python3 -m forgel_code`, если файл не найден.
- pipx упоминается только как явно необязательная альтернатива, одной фразой, после инструкций с pip, и не является первой командой раздела.
- Подраздел обновления даёт путь обновления через pip для более новой закреплённой версии, включая случай, когда номер версии не изменился (переустановка поверх), и подтверждение результата через `forgel-code --version`.
- Каждая показанная команда работает как написано при наличии только Python ≥3.9 и git: без editable-установки, без предположения о чём-либо кроме PyPI и git-адресов, без скрытых предварительных условий.
- Сохраняются прежние оговорки: правило закреплённой версии, отсутствие зависимостей и отсутствие требования к изолированной сборке, необходимость доступного движка через `forgel`, `--engine` или `$FORGEL_ENGINE`.
- Добавляется проверка документации: первая команда установки использует обычный pip, а pipx появляется только после неё и помечен как необязательный.
- Добавляется проверка упаковки: реальная установка копии репозитория обычным pip во временный каталог без сети даёт исполняемый файл `forgel-code`, который запускается.

## Acceptance Criteria

- **AC-1**: Читатель, у которого есть только интерпретатор Python и git, выполняет первую команду раздела установки и получает работающий вывод `forgel-code --version`.
- **AC-2**: Первая команда установки в README использует `python3 -m pip`, и ни одна команда перед ней не устанавливает другой инструмент.
- **AC-3**: pipx описан как необязательный и стоит после инструкций с обычным pip.
- **AC-4**: README показывает и установку в виртуальное окружение, и установку с `--user`, а также исправление PATH и запасной запуск `python3 -m forgel_code`.
- **AC-5**: Подраздел обновления ставит более новую закреплённую версию через обычный pip и объясняет, что делать при неизменившемся номере версии.
- **AC-6**: Новая проверка документации падает, если первая команда перестала быть установкой через pip или pipx потерял пометку «необязательно».
- **AC-7**: Новая проверка упаковки ставит копию репозитория обычным pip во временный каталог и успешно запускает полученный `forgel-code`.
- **AC-8**: `python3 -m unittest discover -s tests` проходит полностью.

## Assumptions

- Версия остаётся 0.1.0, поэтому примеры закрепляются на v0.1.0 и на точном номере `forgel-code==0.1.0`.
- Основной путь — `python3 -m pip`, который работает и там, где имя запускаемого файла `pip` неоднозначно или отсутствует.
- В репозитории клиента уже есть `forgel_code/__main__.py`, поэтому `python3 -m forgel_code` годится как запасной запуск.
- Репозиторий публичный и ставится через `git+https://github.com/forgel-dev/code@<версия>`; примеры с обычным pip используют эту форму.
- Проверка установки доказывает механику без сети на локальной копии, а сам удалённый адрес проверяется вручную и отмечается в отчёте.
