## Overview

Довести клиент Forgel Code до состояния, пригодного для альфа-проверки: выбранный проект передаётся движку во всех командах, машинный вывод остаётся ровно одним JSON-объектом даже на ошибках аргументов, вызов движка устойчив (ограничение по времени, UTF-8, изолированный ввод, разбор структурированной ошибки, трактовка ok=false как неуспеха), хрупкие места разбора устранены, упаковка корректна и установка фиксируется на конкретной версии. Предыдущий прогон сорвался на зацикливании агента и на непригодной форме команд проверки; новая задача должна проходить проверку одной командой запуска тестов из корня репозитория и закрывать два ранее непроверенных критерия.

## Goals

- R1. Ключ выбранного проекта передаётся движку во всех командах, работающих с проектом: status, tasks, task, say, plan, resume, pause, history, projects, session, accept, rework. После выбора проекта ни одна из этих команд не обращается к проекту, активному в движке по умолчанию.
- R2. При машинном выводе любая ошибка разбора аргументов (неизвестная команда, лишний или отсутствующий аргумент) выдаёт ровно один JSON-объект с "ok": false и ненулевой код возврата; текст справки разборщика в stdout не попадает.
- R3. Вызов движка ограничен по времени; по истечении ограничения клиент завершается ненулевым кодом и структурированной ошибкой, а не зависает.
- R4. Вывод движка читается как UTF-8 независимо от локали системы.
- R5. Дочерний процесс движка не наследует стандартный ввод клиента.
- R6. При ненулевом коде возврата движка структурированная ошибка (объект с "ok": false и описанием) разбирается и передаётся пользователю в том же формате, что и остальные ответы, а не подменяется сырым текстом потоков.
- R7. Ответ движка с "ok": false при нулевом коде возврата трактуется как неуспех на уровне вызова движка и приводит к ненулевому коду возврата клиента.
- R8. Глобальные флаги (машинный вывод, путь к движку) распознаются без потери содержимого аргументов: текст, содержащий похожие слова, и замечания, начинающиеся с дефиса, доходят до движка без искажений.
- R9. Поиск задачи по идентификатору однозначен и не принимает за задачу первый вложенный объект с полем идентификатора; при неоднозначности или отсутствии задачи выдаётся ошибка.
- R10. Отсутствие команды в движке определяется по устойчивому признаку ответа, а не по подстрокам текста сообщения об ошибке.
- R11. Поле проекта в машинном ответе отражает фактически использованный проект; при отсутствии выбранного проекта не подставляется ярлык по умолчанию.
- R12. Клиент поддерживает вывод версии и при ошибке сообщает, какой движок отвечал.
- R13. Команда plan однозначно различает текст цели и имя вехи; текст цели не уходит движку как имя вехи.
- R14. Архив исходников соответствует PEP 625: имя forgel_code-<версия>, метаданные пакета в корне архива.
- R15. Колесо пакета включает подпакеты, файл типов и файлы данных, а не только модули верхнего уровня.
- R16. Версия пакета задаётся в одном месте и используется и метаданными, и сборочным backend.
- R17. Инструкция по установке ставит зафиксированную копию (конкретный коммит, тег или собранный пакет), не ветку по умолчанию и не режим разработки; описано обновление поверх установленной копии.
- R18. На каждый исправленный пункт добавлен тест; тесты падают на исходном коде и проходят после правки.
- R19. Проверка запускается одной командой из корня репозитория клиента и завершается успешно.

## Technical Requirements

- Клиент остаётся тонким: он не обращается к модели, не читает файлы проекта и не выполняет проверки сам.
- Клиент не импортирует код движка; взаимодействие только через отдельный процесс и параметризованные команды.
- Согласованный машинный формат: при машинном выводе ровно один JSON-объект в stdout, код 0 при успехе, ненулевой код и "ok": false при ошибке.
- Изменения только в репозитории клиента; движок и его контракт команд не меняются.
- Публичные артефакты — на английском; ответы в чате — на русском.
- Тесты не запускают внешние сервисы и не требуют сети.

## Acceptance Criteria

- **AC-1**: Команда `python -m unittest discover -s tests` из корня репозитория клиента завершается с кодом 0 и без ошибок импорта.
- **AC-2**: `forgel-code --help` и `forgel-code --version` завершаются с кодом 0.
- **AC-3**: После `forgel-code use <key>` команды status, tasks, task, say, plan, resume, pause, history, projects, session передают движку выбранный проект (проверяется тестом с подставным движком, фиксирующим аргументы).
- **AC-4**: Вызов с `--json` и заведомо неверными аргументами (неизвестная команда, лишний позиционный аргумент) печатает ровно один JSON-объект с "ok": false и завершается ненулевым кодом; справка разборщика в stdout отсутствует.
- **AC-5**: Подставной движок, зависающий дольше заданного ограничения, приводит к ненулевому коду возврата и структурированной ошибке в пределах ограничения плюс запас.
- **AC-6**: Ответ движка с ненулевым кодом и объектом ошибки доносит до пользователя поля этой ошибки.
- **AC-7**: Ответ движка с "ok": false и нулевым кодом приводит к ненулевому коду возврата клиента.
- **AC-8**: `forgel-code say "добавь флаг --json"` передаёт движку полный текст без потери слов (проверяется тестом).
- **AC-9**: Команда plan с текстом цели передаёт движку текст цели, а не имя вехи.
- **AC-10**: Сборка архива исходников даёт имя forgel_code-<версия> и содержит метаданные пакета в корне; сборка колеса включает подпакеты и файл типов — проверяется тестом упаковки.
- **AC-11**: README не содержит установки с ветки по умолчанию и не предлагает режим разработки; установка фиксируется на коммите, теге или собранном пакете.
- **AC-12**: Набор тестов остаётся зелёным целиком, ни один существующий тест не ослаблен.

## Assumptions

- Целевой репозиторий — code: задача целиком про клиент Forgel Code, который живёт в отдельном репозитории и не импортирует движок.
- Проверка задаётся запуском по каталогу тестов из корня репозитория, а не адресацией модулей: прошлый прогон показал, что адресация модулей в окружении исполнения не работает, а запуск по каталогу проходит полностью. Это обратимое решение и не меняет структуру тестов.
- Агент должен сначала свериться с текущим состоянием файлов, потому что часть исправлений могла быть внесена прошлым прогоном, и не переписывать уже корректное.
- Ограничение по времени вызова движка выбирается консервативным значением по умолчанию с возможностью переопределения через переменную окружения; конкретное значение — на усмотрение реализации.
- Два ранее непроверенных критерия (установка не с плавающей ветки и доказательство падения новых тестов на исходном коде) входят в эту задачу и проверяются в её приёмке.
