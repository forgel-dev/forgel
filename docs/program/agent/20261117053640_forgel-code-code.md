## Overview

Наполнить второй публичный репозиторий `code` (организация `forgel-dev`) тонким Python-клиентом `forgel-code`. Клиент не импортирует движок и работает только через уже описанные параметрические команды движка с машинно-читаемым ответом: он не зовёт модель, не читает файлы проекта и не запускает проверки сам. В этом шаге движок не меняется — `forgel chat`, консоль и Telegram продолжают работать как раньше; вынос консоли и последующее удаление заменённого режима чата остаются следующими шагами.

## Goals

- Клиент живёт в репозитории `code` (публичный, организация `forgel-dev`), ставится одной командой и даёт исполняемую команду `forgel-code`.
- Клиент ничего не импортирует из движка: единственный канал связи — запуск `forgel <команда> --json` как отдельного процесса и разбор ровно одного JSON-объекта из stdout.
- Объём по Парето: свободная фраза превращается в задачу; состояние по задаче и по вехе; принять задачу; отправить на доработку с замечаниями; запустить и приостановить работу; разложить цель вехи на задачи; короткая история сессии.
- Каждая команда клиента ложится на существующую команду движка; если для пункта из объёма такой команды нет, клиент сообщает об этом явно, а не изобретает поведение.
- Без флага клиент печатает человекочитаемый текст, с флагом — ровно один JSON-объект в stdout.
- Ошибка движка (ненулевой код возврата и тело с описанием) доносится до пользователя текстом движка, а клиент завершается с ненулевым кодом и не глотает её.
- Активный проект — сессия клиента с ключом по умолчанию `local`; есть явный выбор и список проектов через команды движка.
- Репозиторий содержит README с установкой и списком команд, лицензию Apache-2.0 и собственные тесты.
- Движок в этом шаге не меняется: `forgel chat`, консоль и Telegram остаются работоспособными, файлы движка не правятся.

## Summary

Репозиторий `code` наполнен тонким клиентом `forgel-code`.

Что сделано:
- `pyproject.toml` — пакет `forgel-code` с точкой входа `forgel-code = forgel_code.cli:main`, Apache-2.0, без зависимостей; установка одной командой (`pipx install git+...` или `pip install .`).
- `forgel_code/engine.py` — единственный канал связи с движком: запуск `forgel <команда> --json` отдельным процессом (`subprocess.run`), разбор ровно одного JSON-объекта из stdout. Ненулевой код возврата движка превращается в `EngineError` с текстом движка (stderr, иначе stdout), код клиента ненулевой, ошибка не глотается. Отсутствующий исполняемый файл движка тоже репортится.
- `forgel_code/cli.py` — команды объёма Парето: `say`, `status`, `tasks`, `task`, `accept`, `rework`, `resume`, `pause`, `plan`, `history`, `projects`, `session`, `use`. Каждая ложится на одноимённую команду движка и всегда вызывает её с `--json`. Для `accept` и `rework` команды движка нет — клиент явно сообщает об этом (код 2, текст «the engine has no command ...») и ничего не выдумывает, к движку не обращается. Флаг `--json` клиента управляет только его собственным выводом: без флага — человекочитаемый текст, с флагом — ровно один JSON-объект (`command`, `project`, `ok`, `result`; при ошибке `error` и ненулевой код). Флаги `--json`/`--engine` работают и до, и после имени команды.
- `forgel_code/session.py` — сессия клиента с активным проектом, ключ по умолчанию `local`; `use <key>` явно выбирает и сохраняет проект, `projects` идёт в движок. Каталог сессии переопределяется `FORGEL_CODE_HOME`.
- `forgel_code/render.py` — рендер ответа движка в текст.
- `LICENSE` — Apache-2.0; `README.md` — установка, таблица всех команд с соответствующими командами движка, формат вывода, активный проект, чего клиент не покрывает, запуск тестов.
- `tests/test_cli.py` — 18 тестов на `unittest`: подставной движок на PATH (`forgel`, отдающий заранее заданный JSON и записывающий свой argv), проверка argv каждой команды (всегда `--json`), текст без флага, ровно один JSON-объект с флагом, ошибка движка → ненулевой код + текст движка, явное сообщение для неподдерживаемых `accept`/`rework`, сессия и проект по умолчанию `local`, сохранение выбора `use`, а также статическая проверка через `ast`, что исходники клиента импортируют только stdlib и не упоминают пакет движка.

Проверено: `python -m unittest discover -s tests` — 18 тестов, OK. `python -m forgel_code --help` перечисляет ровно команды из объёма Парето. Файлы движка не менялись: правки только в репозитории `code`.
