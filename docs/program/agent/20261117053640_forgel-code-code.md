## Overview

Наполнить второй публичный репозиторий `code` (организация `forgel-dev`) тонким Python-клиентом `forgel-code`. Клиент не импортирует движок и работает только через уже описанные параметрические команды движка с машинно-читаемым ответом: он не зовёт модель, не читает файлы проекта и не запускает проверки сам. В этом шаге движок не меняется — `forgel chat`, консоль и Telegram продолжают работать как раньше; вынос консоли и последующее удаление заменённого режима чата остаются следующими шагами.

## Goals

- Клиент живёт в репозитории `code` (публичный, организация `forgel-dev`), ставится одной командой и даёт исполняемую команду `forgel-code`.
- Клиент ничего не импортирует из движка: единственный канал связи — запуск `forgel <команда> --json` как отдельного процесса и разбор ровно одного JSON-объекта из stdout.
- Объём по Парето: свободная фраза превращается в задачу; состояние по задаче и по вехе; принять задачу; отправить на доработку с замечаниями; запустить и приостановить работу; разложить цель вехи на задачи; короткая история сессии.
- Каждая команда клиента ложится на существующую команду движка; если для пункта из объёма такой команды нет, клиент сообщает об этом явно, а не изобретает поведение.

- Ошибка движка (ненулевой код возврата и тело с описанием) доносится до пользователя текстом движка, а клиент завершается с ненулевым кодом и не глотает её.
- Активный проект — сессия клиента с ключом по умолчанию `local`; есть явный выбор и список проектов через команды движка.
- Репозиторий содержит README с установкой и списком команд, лицензию Apache-2.0 и собственные тесты.

## Summary

Клиент `forgel-code` в репозитории `code` приведён в соответствие с реальным命令行 движка.

Что исправлено по замечаниям ревью:
- `accept` и `rework` больше не заглушки. `forgel-code accept <task>` вызывает движок как `forgel task accept --project <key> --task <task> --json`, а `forgel-code rework <task> <замечания...>` — как `forgel task reject --project <key> --task <task> --reason "<замечания>" --json`. Проект берётся из сессии клиента (по умолчанию `local`, меняется `use`). Замечания обязательны: без них клиент не вызывает движок и завершается с ошибкой использования.
- `forgel-code task <task>` больше не шлёт несуществующий `forgel task <id> --json`. Клиент запрашивает `forgel tasks --json` и выбирает из машинно-читаемого ответа ровно запрошенную задачу; если её нет — сообщает об этом и завершается с ненулевым кодом (текст и JSON с `ok: false`).
- `forgel-code plan <milestone> [goal...]` теперь соответствует командной строке движка: `forgel plan <milestone>` и, при наличии формулировки цели, `forgel plan <milestone> --goal "<goal>"`. Без аргументов остаётся `forgel plan`.
- Удалён словарь `UNSUPPORTED` и ложное утверждение «no engine command yet» из README; в README таблица команд переписана под реальные команды движка (`forgel task accept|reject --project … --task …`, `forgel plan <milestone> [--goal …]`).

Остальное сохранено: пакет `forgel_code` с точкой входа `forgel-code = forgel_code.cli:main`, Apache-2.0, единственный канал связи — `subprocess.run(["forgel", … , "--json"])` и разбор ровно одного JSON-объекта, ошибка движка (ненулевой код + текст) доносится пользователю и даёт ненулевой код клиента, `--json` клиента управляет только его собственным выводом.

Тесты (`python -m unittest discover -s tests`) — 24 теста, OK. Подставной движок на PATH фиксирует argv и отдаёт заданный JSON; проверено, что каждая команда объёма Парето доходит до движка с ожидаемым argv, печатает текст без флага и ровно один JSON-объект с флагом, что ошибки движка не глотаются, что `accept`/`rework` реально вызывают движок (и с активным проектом из сессии), что `task` показывает только запрошенную задачу, и что в исходниках клиента нет импорта пакета движка. Файлы движка не менялись.
