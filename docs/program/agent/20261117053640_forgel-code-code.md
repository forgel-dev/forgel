## Overview

Наполнить второй публичный репозиторий `code` (организация `forgel-dev`) тонким Python-клиентом `forgel-code`. Клиент не импортирует движок и работает только через уже описанные параметрические команды движка с машинно-читаемым ответом: он не зовёт модель, не читает файлы проекта и не запускает проверки сам. В этом шаге движок не меняется — `forgel chat`, консоль и Telegram продолжают работать как раньше; вынос консоли и последующее удаление заменённого режима чата остаются следующими шагами.

## Goals

- Клиент живёт в репозитории `code` (публичный, организация `forgel-dev`), ставится одной командой и даёт исполняемую команду `forgel-code`.
- Клиент ничего не импортирует из движка: единственный канал связи — запуск `forgel <команда> --json` как отдельного процесса и разбор ровно одного JSON-объекта из stdout.
- Объём по Парето: свободная фраза превращается в задачу; состояние по задаче и по вехе; принять задачу; отправить на доработку с замечаниями; запустить и приостановить работу; разложить цель вехи на задачи; короткая история сессии.
- Каждая команда клиента ложится на существующую команду движка; если для пункта из объёма такой команды нет, клиент сообщает об этом явно, а не изобретает поведение.
- Без флага клиент печатает человекочитаемый текст, с флагом — ровно один JSON-объект в stdout.
- Ошибка движка (ненулевой код возврата и тело с описанием) доносится до пользователя текстом движка, а клиент завершается с ненулевым кодом и не глотает её.
- Активный проект — сессия клиента с ключом по умолчанию `local`; есть явный выбор и список проектов через команды движка.
- Репозиторий содержит README с установкой и списком команд, лицензию Apache-2.0 и собственные тесты.
- Движок в этом шаге не меняется: `forgel chat`, консоль и Telegram остаются работоспособными, файлы движка не правятся.

## Summary

Исправлена блокирующая проблема ревью: `accept` и `rework` теперь ложатся на реальный интерфейс движка — `forgel task accept --task <task> --json` и `forgel task reject --task <task> --notes "<замечания>" --json` (позиционное действие у `task`, `--accept` больше не используется как флаг). Подставной движок в tests/test_cli.py переписан так, чтобы действительно повторять парсер движка: `task` требует позиционное действие (`accept`, `reject`, ...), набор известных опций фиксирован, опции с обязательным значением проверяются (в т.ч. `--accept` со значением), неизвестные опции и лишние позиционные аргументы отвергаются, `invalid choice` для неизвестного действия. Добавлен класс StubContractTest: он доказывает, что подставной движок отвергает старую (сломанную) форму вызова (`task --task X`, `task accept --accept --task X`, `--reason`) и принимает реально используемые клиентом вызовы. Сообщение «no engine command» теперь ссылается на `forgel task accept` / `forgel task reject` и по-прежнему применяется только к unknown/unrecognized/invalid choice, не подменяя обычные ошибки движка. README обновлён под новые вызовы. Запуск: `python -m unittest discover -s tests` — 38 тестов, OK. Файлы движка не менялись (в репозитории только клиент).
