## Summary

The client package, README, Apache-2.0 license and unittest suite are present in the `code` repository, the executable `forgel-code` is declared, every engine call goes through a subprocess with `--json` appended, human/JSON output and engine-error propagation look correct, and the engine repository is untouched. However the accept/rework mapping was rewritten to use engine argument shapes the engine does not have: `forgel-code rework` always sends `--reason`, while the engine's `task` parser only knows `--notes` (`src/forgel/client.py` task subparser), so the command dies on an engine argparse error and the remarks never reach the engine; `accept`/`rework` also pass the client session key (default `local`) into the engine's `--project`, which the engine resolves as a project id via `resolve_project`, so the default active project is rejected as `unknown project 'local'`. The stub engine in the tests accepts any argv, so these contract breaks are not caught.
