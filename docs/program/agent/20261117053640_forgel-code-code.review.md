## Summary

The `code` repository now holds a thin `forgel-code` client with a proper package layout, entry point, README, Apache-2.0 LICENSE and unittest suite, and it never imports the engine (only `forgel <cmd> --json` subprocesses). However two Pareto-scope items do not map onto real engine commands: `accept`/`rework` are declared 'no engine command yet' and exit 2 without calling the engine, although the engine in this repo already exposes `forgel task accept` and `forgel task reject` (README, src/forgel/client_cli.py). The `task` and `plan` wrappers also emit argv that the engine does not accept (`forgel task <id> --json` instead of `forgel task accept|reject|… --project <id> --task <id>`; `forgel plan <goal> --json` instead of `forgel plan <id> --goal "…"`), so those client commands would fail against the real engine — the stub engine in the tests hides this. FR-3, FR-4 and AC-2 are therefore not met.
