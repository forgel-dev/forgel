## Summary

The `code` repository is well built: a dependency-free wheel with a real `forgel-code` console script, a subprocess-only engine channel that parses exactly one JSON object, human/JSON output modes where `--json` prints one object (errors keep the engine text on stderr and a non-zero exit), a local session default of `local`, Apache-2.0 LICENSE, English README, a `unittest` suite and a static no-engine-import style check. The engine files are untouched because the client lives in its own repository, and the engine's own suite still passes. The blocking problem is the accept/rework mapping: the README and the client's `TASK_ACTIONS`/`UNKNOWN_ACTION_MARKERS` machinery invoke `forgel task --accept --task <id>` and `forgel task --task <id> --notes <remark>`, but the engine's `task` subcommand requires an `--json`-aware `action` positional (`accept|reject|retry|cancel|add`) and its `--accept` option takes a value. Both calls therefore always die in the engine's argparse with a non-zero code, so two of the seven Pareto capabilities (accept a task, send it back for rework with remarks) never reach the engine even though `forgel task accept` / `forgel task reject --notes` exist. The test stub was written to accept the invented flag form and omits the required `action` positional, so the tests keep passing while the real contract is broken.
