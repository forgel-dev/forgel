## Overview

The Forgel Code client repository (repo `code`) contains defects that make its commands unusable and its test suite non-executable: commands that operate on a project do not forward the selected project key to the engine (so they hit the engine's default project), argument-parsing errors pollute stdout with parser help and break the single-JSON-object machine contract, engine invocation has no timeout, decodes with the platform locale, inherits stdin, discards structured engine errors on non-zero exit, and ignores `ok: false` with exit code 0; global flags are matched by naive text substitution so `say "добавь флаг --json"` is corrupted; task lookup by id can pick a nested object; missing-command detection relies on substrings of error text; plan confuses goal text with a milestone name; the project field in machine output is not the project actually used; there is no `--version`; the sdist/wheel are misnamed or incomplete and the version is duplicated; and the README install instructions point at a branch or an editable/dev install. The suite cannot even be run as one command from the repository root, so none of these defects is guarded by a test.

**Outcome:** The client repository at `code` passes `python -m unittest discover -s tests` from its root with exit code 0; every listed command forwards the selected project key to the engine; machine mode emits exactly one JSON object with `ok: false` and a non-zero exit code for every failure, including argument-parsing errors and timeouts; the engine is invoked with a timeout, UTF-8 decoding, no inherited stdin, structured error passthrough, and `ok: false` treated as failure; global flags no longer corrupt argument text; task lookup by id is unambiguous; missing-command detection uses a stable signal; `plan` passes goal text as goal text; `--version` works and failures name the engine; packaging produces a PEP 625 sdist and a complete wheel from a single version source; and the README documents a pinned, non-dev install plus an upgrade path.

## Goals

- Make the client's test suite runnable as one command from the repository root and green.
- Make the selected project key reach the engine for every project-scoped command.
- Make machine-mode output a single well-formed JSON object for all failures, including parse errors, timeouts and engine errors.
- Make engine invocation bounded, UTF-8-safe, stdin-isolated and error-transparent, treating `ok: false` as failure.
- Make argument handling non-destructive for global flags and unambiguous for `plan` and task-id lookup.
- Make the client report its version and identify the engine on failure.
- Make packaging PEP 625-compliant, complete and single-sourced for the version.
- Make the README install instructions pinned and upgradeable.

## Functional Requirements

- **FR-1**: R1. After `forgel-code use <key>`, each of status, tasks, task, say, plan, resume, pause, history, projects, session, accept, rework passes the selected project key to the engine, and none of them relies on the engine's default project.
- **FR-2**: R1a. A test with a fake engine that records argv asserts, for every command in R1, that the recorded arguments contain the selected key and no default-project key.
- **FR-3**: R2. With machine output enabled (`--json`), any argument-parsing failure (unknown command, extra positional, missing required argument) writes exactly one JSON object with `"ok": false` and a description to stdout, writes no parser help text to stdout, and exits non-zero.
- **FR-4**: R3. Every engine invocation is bounded by a timeout; when it elapses the client kills the engine, exits non-zero and emits a structured error, and returns within the timeout plus a small fixed margin.
- **FR-5**: R4. Engine stdout and stderr are decoded as UTF-8 regardless of the host locale.
- **FR-6**: R5. The engine child process is started without inheriting the client's standard input.
- **FR-7**: R6. When the engine exits non-zero and emits a structured error object, the client parses it and surfaces its fields through the same structured (machine) or rendered (human) channel used for other responses, rather than replacing it with raw stdout/stderr text.
- **FR-8**: R7. An engine response with `"ok": false` and exit code 0 is treated as a failed engine call and makes the client exit non-zero.
- **FR-9**: R8. Global flags (machine output, engine path) are parsed as positional-free options so argument text is preserved: arguments that merely contain similar words and remarks beginning with a hyphen reach the engine byte-for-byte unchanged.
- **FR-10**: R9. Task lookup by identifier resolves exactly one task; a nested object that merely carries an id field is never accepted as the task; ambiguity or absence produces an error.
- **FR-11**: R10. Detection of a missing engine command uses a stable property of the engine response, not substrings of the human-readable error message.
- **FR-12**: R11. The project field in machine output reports the project actually used for the call; when no project is selected no default label is substituted.
- **FR-13**: R12. `forgel-code --version` prints the client version and exits 0; when a call fails, the error message identifies which engine responded (engine identity/version or path).
- **FR-14**: R13. `plan` distinguishes goal text from a milestone name; goal text is sent to the engine as goal text and is never sent as a milestone name.
- **FR-15**: R14. The built source distribution is named `forgel_code-<version>` and contains the package metadata at the archive root.
- **FR-16**: R15. The built wheel contains the package subpackages, the type file and the data files, not only top-level modules.
- **FR-17**: R16. The package version is declared in exactly one place and consumed by both the package metadata and the build backend.
- **FR-18**: R17. The README install instructions install a pinned copy (a specific commit, tag or built package), not the default branch and not a development/editable install, and describe upgrading over an installed copy.
- **FR-19**: R18. Each fixed item R1-R17 has a test that fails on the pre-fix code and passes after the fix.
- **FR-20**: R19. The whole suite runs with one command from the client repository root (`python -m unittest discover -s tests`) and exits 0 without import errors.

## Risks

- The engine's stable missing-command signal is not documented here; if the engine only returns a free-text message, R10 cannot be met without an engine change, which is out of scope, so the client would have to key on exit code plus a structured field — this needs confirmation against the engine.
- The requirement list R1-R19 is very broad for a single repository change; a coding agent may run out of room and land a partial fix that still satisfies the packaging or CLI tests but not, for example, the timeout or `ok: false` paths.
- Tests asserting exact fake-engine argv can become brittle if the engine's argument shape changes; the tests should assert presence of the key rather than exact ordering.
- The timeout test can be flaky on a loaded machine if the margin is too tight; it must use a margin large enough for CI variance while still proving the client returns.
- Packaging tests that shell out to a build backend can be slow or can fail in an offline environment; if the backend needs network the test must call the backend directly instead.
- The engine's error object field names are assumed rather than documented; a wrong assumption makes R6 pass against a fake but fail against the real engine.
- R18 ('tests fail on the original code') cannot be proven inside a single commit; it is satisfied by construction and can only be reviewed.

  ```
  #!/usr/bin/env python3
  import json, os, sys, time
  
  COMMANDS = {'status','tasks','task','say','plan','resume','pause','history','projects','session','accept','rework'}
  ENGINE = {'name': 'forgel-stub', 'version': '0.0.0'}
  
  def emit(obj, code=0):
      print(json.dumps(obj, ensure_ascii=False, sort_keys=True), flush=True)
      raise SystemExit(code)
  
  def project_of(args):
      for i, a in enumerate(args):
          if a == '--project' and i + 1 < len(args):
              return args[i+1]
          if a.startswith('--project='):
              return a.split('=', 1)[1]
      return None
  
  def main(argv):
      log = os.environ.get('FORGEL_STUB_LOG')
      if log:
          with open(log, 'a', encoding='utf-8') as f:
              print(json.dumps(argv, ensure_ascii=False), file=f)
      sleep = os.environ.get('FORGEL_STUB_SLEEP')
      if sleep:
          time.sleep(float(sleep))
      canned = os.environ.get('FORGEL_STUB_STDOUT')
      if canned is not None:
          sys.stdout.write(canned)
          sys.stdout.flush()
          raise SystemExit(int(os.environ.get('FORGEL_STUB_EXIT', '0')))
      if not argv or argv == ['--help']:
          emit({'ok': True, 'engine': ENGINE, 'commands': sorted(COMMANDS)})
      if argv[0] in ('--version', 'version'):
          emit({'ok': True, 'engine': ENGINE})
      cmd = argv[0]
      if cmd not in COMMANDS:
          msg = 'unsupported command: ' + cmd
          emit({'ok': False, 'engine': ENGINE, 'code': 'unsupported_command', 'unsupported_command': True, 'error': {'code': 'unsupported_command', 'description': msg}, 'description': msg}, 2)
      emit({'ok': True, 'engine': ENGINE, 'command': cmd, 'args': argv[1:], 'project': project_of(argv[1:])})
  
  if __name__ == '__main__':
      main(sys.argv[1:])
  ```
