## Summary

The change set implements the requested shell detection, per-shell profile selection, guarded PATH block, fresh-shell verification and multi-file uninstall cleanup, and the recorded suites pass. However, the mandatory bounded fresh-shell check is not actually enforced: `verify_profile` ignores the watchdog's kill status, and the watchdog only sends SIGTERM, which an interactive bash ignores. A hanging login shell can therefore be reported as verified or hang the installer indefinitely instead of producing the required failure report. A predictable temporary path also introduces a local symlink race. These are blocking defects in the verification path the release claims to add.

## Findings

- [major] code: `bounded_run` records a watchdog kill as `BOUNDED_STATUS=124`, but `verify_profile` never reads `BOUNDED_STATUS` or the killed marker. It returns success whenever the captured output contains `forgel-fresh-resolved=$LAUNCHER`, so a fresh login shell that prints the resolution and then hangs (for example in a blocking `.zlogout`/EXIT trap) is killed by the watchdog yet still reported as verified. This contradicts the requirement that a killed shell be treated as a verification failure. — In `verify_profile`, check `BOUNDED_STATUS`/the killed marker first and fail with the standard report whenever the shell had to be killed, regardless of partial output; add a test whose fresh shell prints the resolution marker and then sleeps.
- [major] code: The watchdog only sends SIGTERM (`kill -TERM "$child"`). The verification shell is started with `-i`, and interactive bash ignores SIGTERM. If the detected login shell is bash and a startup file never returns, `wait "$child"` blocks forever: the installer never exits and never prints the required failure message naming the profile and PATH. The watchdog test uses a `#!/bin/sh` stub that dies on SIGTERM, so this case is not covered. — Escalate to SIGKILL after a short grace period and/or signal the whole process group, and add a test using a TERM-ignoring/interactive-bash-like login shell.
- [minor] code: The watchdog uses predictable paths under `${TMPDIR:-/tmp}` (`forgel-code-check.$$`, `.out`, `.done`, `.killed`) and truncates with `: >`. In a shared `/tmp`, another local user can pre-create a symlink for a guessed PID and cause the installer to truncate an arbitrary file writable by the installing user (local symlink race). — Create a private directory with `mktemp -d` (mode 0700) and keep the marker files inside it, rather than using predictable names under the shared temporary directory.
- [minor] code: `detect_login_shell` accepts a handled shell by basename, so a bare `$SHELL` such as `bash` is returned unchanged. `verify_profile` then evaluates `[ -x "$shell" ]` against the relative path and skips the check, producing a spurious verification failure even though the shell is available on PATH. — Resolve the detected shell with `command -v` (or require and validate an absolute executable path) before using it for verification.
- [minor] code: `CHANGELOG.md` records only the `FORGEL_CODE_PROFILE` uninstall fix under `## [Unreleased]`; the release's headline change (login-shell detection, per-shell profile selection, guarded block and fresh-shell verification) has no changelog entry. — Add an `### Changed`/`### Fixed` entry under `## [Unreleased]` describing the installer PATH detection and fresh-shell verification change.
