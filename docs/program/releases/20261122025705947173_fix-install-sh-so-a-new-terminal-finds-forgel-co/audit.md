# Release audit 20261122025705947173_fix-install-sh-so-a-new-terminal-finds-forgel-co

- Round: 1
- Verdict: fail
- At: 2026-11-22T17:33:00+00:00

## Summary

The release implements most of the PATH detection, guarded block, fresh-shell verification and uninstall work, and the suite passes, but blocking defects remain. The fresh-shell watchdog creates predictable world-readable files under /tmp, ignores its timeout status when deciding success, and can still hang on a shell that ignores SIGTERM. Re-installing over a pre-existing profile also accumulates the separator blank line, so the profile is not byte-identical across runs.

## Findings

- [critical] code: `bounded_run` creates its state files at predictable paths `${TMPDIR:-/tmp}/forgel-code-check.$$.{out,done,killed}` and initializes them with `: >` instead of a private `mktemp` file. A local user can pre-create a symlink for a guessed PID and cause the installer to truncate an arbitrary file writable by the installing user. The redirected fresh-shell output is also created with the default umask and may be readable by other users. — Create a private temporary directory with `mktemp -d` (mode 0700), create files with mode 0600, clean up the directory, and avoid following pre-existing symlinks.
- [major] code: `verify_profile` ignores `BOUNDED_STATUS`. `bounded_run` sets it to 124 when the watchdog kills the shell, but if the captured output already contains `forgel-fresh-resolved=<launcher>`, `verify_profile` returns success. In addition, the watchdog only sends SIGTERM and the parent then blocks in `wait "$child"`, so a shell that ignores SIGTERM defeats the bounded time limit. The watchdog test only covers a shell that prints nothing and dies on TERM. — Treat `BOUNDED_STATUS=124` as a verification failure regardless of captured output, escalate from SIGTERM to SIGKILL after a grace period, and add a test where the detected shell prints the expected resolution and then hangs or ignores TERM.
- [major] code: Re-install idempotence is not preserved for a profile that already contains user content. `add_profile_block` appends a blank line before the block whenever the file is non-empty, while the unchanged `remove_profile_block` is documented to keep every other line. Each re-run therefore leaves an additional separator blank line, violating the requirement that the rest of the file stay byte-identical. The new idempotence tests only cover an initially empty profile. — Remove the installer-added separator along with the marked block, or avoid adding a new separator when the preceding content already ends with a blank line. Add a test that seeds the profile with user content, runs install twice, and asserts exact bytes.
- [minor] code: `detect_login_shell` accepts `$SHELL` when its basename is handled, but `verify_profile` only starts it when `[ -x "$shell" ]`. A valid `SHELL=zsh` (a bare command name) is detected, the block is written, then verification is skipped and the install exits non-zero even though `zsh` is available on PATH. — Resolve the selected shell with `command -v` before the `-x` check, or return the resolved executable path from detection. Add a test with a bare `$SHELL` name.
- [minor] code: `CHANGELOG.md` says `--uninstall` cleans the override profile in addition to the "six standard profile files", but `install.sh` and `README.md` now clean seven standard files including `~/.bashrc`. — Update the changelog entry to say seven standard profile files, or list the files explicitly.
