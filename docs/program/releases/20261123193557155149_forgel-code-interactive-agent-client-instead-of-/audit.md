- Round: 3
- Verdict: fail
- At: 2026-11-24T04:54:38+00:00

## Summary

The release largely delivers the interactive client: a bare `forgel-code` invocation opens a session, the one-shot and `--json` paths keep their parse, output and exit status, the session shows the selected project, plan/task/release state, routes plain-language accept/rework/retry/pause/resume, clarifies ambiguous input, refuses to carry out adopt/create/secret/config from free text, follows the owner's language across four languages, and masks retained state and failure text; the added suites pass and README/CHANGELOG are present. However, the shared redactor still has a credential-leaking path: when an ordinary noun or adjective sits between a recognized secret label and the actual value, `redact()` masks that intervening word and leaves the real value visible, e.g. `token value is hunter2` is displayed as `token [redacted] is hunter2` and `password field: hunter2` as `password [redacted]: hunter2`. Since that text also becomes the retained state/failure copy, this violates the release's absolute no-secret requirement. The idle refresh also contradicts the 'cheap while idle' requirement by calling the engine's tasks and status commands every 0.5 s for the whole wait. These are release-level defects, so the change set is not publishable as is.

## Findings

- [critical] code: `redact()` in `forgel_code/interactive.py` treats the first word after a recognized secret label as the bound value whenever that word is not in the prose vocabulary. A label followed by an ordinary descriptor therefore masks the descriptor instead of the credential and leaves the actual secret visible. With the shipped code `token value is hunter2` renders as `token [redacted] is hunter2` and `password field: hunter2` renders as `password [redacted]: hunter2` (`_binding` computes the span of `value`/`field` via `_bound_value`, then `copied` jumps past it and the real value is appended untouched). The same leaked text is what `show_state`/`idle_refresh` store in `last_state`/`idle_failure`, so the retention guarantee fails too. This breaks the requirement that no secret, token or key material ever appears in the session or in anything the client keeps. — After a secret label, detect that the next word is a plain descriptor rather than a value (no digits, mixed case, value punctuation, or quoting) and, when a copula or explicit separator follows it, resolve the value past the descriptor instead of masking the descriptor; alternatively mask conservatively through the whole label-to-value phrase. Add direct tests for forms such as `token value is hunter2`, `password field: hunter2`, and `the credential value: hunter2` asserting the value is absent from both the displayed line and the retained state, and cover the same text arriving as an engine error.
- [minor] code: The idle refresh runs an engine `tasks` and `status` invocation every `IDLE_REFRESH_SECONDS` (0.5 s) for as long as the owner waits, regardless of whether anything changed. A session left open for a long time spawns thousands of `forgel ... --json` subprocesses, which does not meet the requirement that idle waiting keep the machine's work essentially unchanged; the visible output is quiet, but the work is continuous. — Back the refresh off (for example refresh after each request plus at a much longer idle interval, or reuse a single long-lived engine call) so an idle session does not spawn engine processes every half second, while keeping the state visible without an explicit status request.
- [minor] code: README and CHANGELOG state that a sentence naming no action, or an unmatched/ambiguous request, 'gets a clarification and performs nothing', but the session forwards a plain sentence that names no action to the project agent (`resolve` returns `kind: say`), which is a request the engine may act on. The README table itself says a plain sentence gets the agent's answer, so the documented behavior contradicts both the implementation and its own table. — Reword the documentation to match the behavior: plain sentences are sent to the project agent; only sentences that look like a task action without a task, or that match several actions, are turned into a clarification. Keep the claim of 'nothing performed' limited to those cases.
